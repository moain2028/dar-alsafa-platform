## SDK وضبط البيئة

استخدم **Flutter Stable 3.47.9 وDart 3.13.7**، وهما الإصدار المستقر الذي اخترته للمشروع بعد التحقق من بيانات الإصدارات الرسمية. لا تستخدم beta أو main للإنتاج. نفّذ:

```bash
flutter channel stable
flutter upgrade
flutter --version
flutter doctor -v
```

إذا كان جهازك يحتوي إصداراً أحدث على قناة stable، تحقق من التوافق وثبّت نتيجة `flutter --version` في التوثيق بدلاً من تغيير المتطلبات عشوائياً. حدّث `environment.sdk` في pubspec ليتوافق مع Dart الفعلي، واستخدم إصدارات packages المتوافقة من pub.dev مع lockfile محفوظ.

شغّل Backend أولاً وفق README:

```bash
cp .env.example .env
npm install
npm run dev
```

لا تضع أسراراً داخل Dart أو Git. مرّر العنوان عبر:

```bash
--dart-define=API_URL=https://YOUR_API_HOST/api
```

للتطوير: Android emulator يستخدم `http://10.0.2.2:3001/api`، وiOS simulator يستخدم `http://127.0.0.1:3001/api`، والهاتف الحقيقي يستخدم IP الجهاز المضيف على LAN. الإنتاج HTTPS فقط. أنشئ إعدادات dev/staging/prod واضحة، وامنع HTTP cleartext وTSل غير الآمن في builds الإنتاج.

## المعمارية المطلوبة

استخدم feature-first architecture نظيفة، وMaterial 3، ودعماً كاملاً للعربية RTL والإنجليزية LTR، وResponsive layout للهاتف والجهاز اللوحي. استخدم الحلول التالية أو بدائل مدروسة موثقة السبب:

- `flutter_riverpod` لإدارة الحالة والاعتماديات وعدم إعادة العمل غير الضروري.
- `go_router` للتنقل والحماية حسب الدور وحالة الجلسة.
- `dio` مع interceptors للمصادقة وتجديد الجلسة عند توفر endpoint، وtimeouts وإعادة محاولة آمنة فقط للطلبات idempotent، وlogging منقّح بلا JWT أو كلمات مرور أو OTP.
- `flutter_secure_storage` لتخزين الجلسة، وعدم حفظ كلمة المرور أو OTP.
- نماذج typed آمنة باستخدام `freezed`/`json_serializable` أو بديل typed مع generation محفوظ.
- `socket_io_client` للتحديثات اللحظية، مع reconnect وpolling fallback وإيقاف الاشتراك عند logout/dispose.
- `intl` للتنسيق العربي والعملة SAR والهللات كأعداد صحيحة.
- `geolocator` و`url_launcher` للموقع وفتح الملاحة عند الحاجة، مع أذونات واضحة ورفض كريم.
- تخزين محلي آمن للسلة وحالة الاتصال، مع استراتيجية offline صريحة: لا تنشئ طلباً وهمياً عند انقطاع الشبكة؛ اعرض queued/retry فقط إذا كان Backend يدعم idempotency.

حالات كل شاشة إلزامية: loading وempty وerror مع retry وsuccess. لا توجد أزرار ميتة أو TODO مخفية أو نصوص placeholder. استخدم نفس الثيم البصري الأخضر/الذهبي الموجود في الويب، مع خط عربي واضح وتحسينات accessibility وtouch targets وSemantic labels.

## تطبيق العميل — نفّذه end-to-end

1. تسجيل الدخول والخروج واستعادة الجلسة وحماية `/auth/me`، مع تجربة خطأ عربية مفهومة.
2. اختيار الفرع المسموح، قائمة المنتجات الحقيقية من `GET /products`، بحث وفئات وتفاصيل المنتج والسعرات والمحطة والتوفر.
3. سلة محفوظة، كميات وملاحظات لكل صنف، محلي/سفري/توصيل حسب الصلاحية، رقم طاولة وعنوان وإحداثيات، كوبون DAR10، وإعادة حساب تقديرية مع اعتبار استجابة الخادم هي السعر النهائي.
4. الدفع: اعرض فقط الخيارات المدعومة من البيئة. وضّح أن البطاقات mock في بيئة التطوير. لا تضف Moyasar/HyperPay/STC Pay حقيقياً بلا مفاتيح وBackend/webhook؛ نفّذ adapter قابلاً للتبديل ولا تدّعِ تحصيلاً.
5. إنشاء الطلب عبر `POST /orders`، شاشة نجاح برقم الطلب، عرض deliveryCode مرة واحدة للعميل، عدم تسجيله في logs.
6. سجل الطلبات وتتبع الحالة لحظياً: PLACED → CONFIRMED → PREPARING → READY → OUT_FOR_DELIVERY → DELIVERED/SERVED، مع socket fallback وتحديث يدوي.
7. الفاتورة من `GET /invoices/:orderId`: البيانات وQR الحقيقي، مشاركة/طباعة إن أمكن، وXML من `/xml`. وضّح أن الفاتورة تطويرية وغير معتمدة ZATCA ما لم تكتمل الشهادة والربط الفعلي.
8. العنوان والموقع والملاحة، حالات رفض الإذن، وإعادة الطلب من البنود الفعلية. أي وظيفة Backend ناقصة مثل المحفظة أو FCM أو الصور أو بث موقع المندوب يجب توثيقها أو تنفيذها كاملة مع اختبارات، لا محاكاتها.

## تطبيق المندوب — نفّذه end-to-end

1. دخول مخصص للدور COURIER، وجلب المهام الحقيقية من `GET /orders` دون عرض مهام مندوب آخر.
2. تبويب نشطة/مكتملة، تفاصيل الفرع والعميل والبنود والعنوان والمبلغ وطريقة الدفع والتحصيل COD والعمولة الفعلية.
3. فتح موقع الفرع/العميل في تطبيق الخرائط، مع fallback للمتصفح وعدم ادعاء مسار مروري محسوب داخل التطبيق.
4. إظهار الجاهزية بدقة. لا تسمح بالتسليم إلا عند `OUT_FOR_DELIVERY`.
5. OTP من 4 أرقام عبر `POST /orders/:id/deliver`، منع الإدخال غير الرقمي والإرسال المكرر، معالجة الرمز الخطأ والشبكة، وعدم تخزين OTP أو طباعته.
6. تحديث الحالة والمهام والعمولة بعد نجاح الخادم فقط. بث الموقع الخلفي وتتبع المندوب الحي لا يُفعّلان إلا بأذونات وBackend فعلي واختبار بطارية وخصوصية؛ وثّق حدود النسخة إن لم ينفذا.
7. دعم reconnect والتزامن وقائمة فارغة واضحة وإشعارات FCM فقط عند توفير إعدادات مشروع Firebase الحقيقية وعدم إدخال مفاتيح خاصة في Git.

## الأمان والجودة

- طبّق RBAC وownership في Backend؛ إخفاء الزر في Flutter ليس حماية.
- لا أسرار أو tokens أو private keys أو google-services حقيقية أو keystores في Git. أضف أنماطها إلى `.gitignore` و`.env.example` بلا قيم حقيقية.
- استخدم certificate pinning فقط مع خطة تدوير صحيحة؛ لا تعطل التحقق من الشهادات ولا تستخدم badCertificateCallback للإنتاج.
- Android: applicationId مهني `sa.daralsafa.customer` و`sa.daralsafa.courier`، أذونات الحد الأدنى، توافق 16 KB page size ومتطلبات Google Play الحالية، وتوقيع release من أسرار CI لا من المستودع.
- iOS: bundle identifiers مقابلة، أذونات الموقع والكاميرا فقط عند الحاجة، وإعدادات Xcode/App Store الحالية. لا تدّعِ build iOS إلا على macOS/Xcode.
- راجع `flutter pub outdated` والثغرات، ولا ترفع dependency دون اختبار التوافق.

## الاختبارات والقبول الإلزامي

اكتب وشغّل، لا تكتفِ بذكرها:

1. Unit tests: الهللات وVAT والخصم، حالات الجلسة، نماذج JSON، حالات الطلب، التحقق من OTP، ومعالجة أخطاء API.
2. Widget tests: RTL، القائمة، السلة، الحالات الفارغة والأخطاء، إنشاء الطلب، قائمة المهام، وشاشة OTP.
3. Integration tests على Backend التجريبي: عميل يسجل → يضيف منتجات → ينشئ طلباً → يتتبعه؛ مندوب يسجل → يرى المهمة → يؤكد OTP الصحيح؛ اختبار OTP خاطئ وصلاحية مرفوضة.
4. شغّل `dart format --output=none --set-exit-if-changed .` و`flutter analyze` و`flutter test` لكل تطبيق والحزمة المشتركة. الهدف صفر أخطاء وصفر تحذيرات قابلة للإصلاح.
5. شغّل `npm run typecheck && npm run lint && npm test && npm run build` عند تعديل Backend.
6. ابنِ Android release لكل تطبيق:
   `flutter build appbundle --release` و`flutter build apk --release` مع dart-define المناسب.
7. على macOS فقط: `flutter build ipa --release` بعد إعداد التوقيع؛ وإلا اكتب صراحة أن iOS لم يُبنَ، دون إيقاف Android.
8. اختبر التطبيقين على جهاز/محاكي فعلي باللمس وبالعربية، وتحقق من الدور والفرع وانقطاع الشبكة وإعادة الفتح ودوران الشاشة.
